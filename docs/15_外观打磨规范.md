## 一、色板 token（单一真相源）

### 1.1 原则

> **中性灰黑为基调；冷调只作「微光」点缀（面积小）。**
> 文字阶梯的蓝偏移 **≤ 12**（`B - R ≤ 12`），不再出现 ΔB-R > 30 的冷蓝文字。

### 1.2 CSS 变量（`app.html` `:root`）

```css
--bg:#08090C; --bg-soft:#0D0E11;              /* 底色 */
--t1:#ECEDEF; --t2:#8C9097; --t3:#4B4E54;     /* 文字阶梯（中性冷白）*/
--accent:#7A828C; --glow:rgba(122,130,140,0.32);  /* 强调（中性灰，非冷钢蓝）*/
--glass:rgba(255,255,255,0.045); --glass-b:rgba(255,255,255,0.08);
--divider:rgba(255,255,255,0.06);
--cool:#93A7BE; --cool-dim:rgba(147,167,190,0.30);  /* 冷调微光（唯一允许的冷色）*/
```

### 1.3 色值映射规则（「压蓝保亮」）

打磨时对冷白文字色族统一按此规则处理：**保持亮度与层次不变，只压蓝偏移**。

| 原值（冷） | 新值（中性） | 说明 |
|---|---|---|
| `rgba(198,214,232,·)` | `rgba(210,216,224,·)` | 列表主文字 |
| `rgba(178,188,204,·)` | `rgba(188,194,202,·)` | 次要文字 |
| `rgba(158,170,186,·)` | `rgba(170,176,184,·)` | 弱化文字 |
| `rgba(226,238,250,·)` | `rgba(232,236,242,·)` | 高亮文字 |
| `rgba(50,90,150,·)` | `rgba(255,255,255,0.11)` | 蓝色语义色 → 中性玻璃 |

> 共替换 **130 处**（JS 绘制层）+ **9 处**（CSS 层）。
> 剩余约 7 处冷蓝是**有意保留的冷调点缀**（token 定义、标题光晕、边缘指示箭头、播放页 wash）。

### 1.4 检查方法

```bash
cd prototype
python3 - <<'EOF'
import re
src=open('app.html',encoding='utf-8').read()
src=re.sub(r'/\*[\s\S]*?\*/','',src)          # 去注释（避免历史记录误报）
cool=[m.group(0) for m in re.finditer(r'rgba?\(\s*\d+\s*,\s*\d+\s*,\s*\d+',src)
      if (lambda r,g,b: b>r+22 and b>60)(*map(int,re.findall(r'\d+',m.group(0))[:3]))]
print('冷蓝残留:', len(cool), '处（≤12 为正常）')
EOF
```

## 三、字号阶梯（单一真相源）

### 3.1 背景

打磨前 JS 侧有 **28 种** `Math.round(x*P)` 系数，CSS 侧有 12/12.5/13、10/10.5/11、15/15.5、18.5 等
「差一点」的档位 → 层次混乱、无系统。

### 3.2 JS 侧：`TS` 常量（10 档）

语义对齐主项目 `LX_Pro_Rebuild/11-视觉设计体系.md` §4.2 的 `LXType`（display/headline/title/body/label 五级）。

```js
const TS = {
  xs:    0.12,   /* labelSmall    11sp —— 极次要：时长、单位、注释 */
  sm:    0.14,   /* labelLarge    13sp —— 次要：副标题、歌手 */
  bodyS: 0.17,   /* bodyMedium     14sp —— 徽章、辅助行 */
  body:  0.20,   /* bodyLarge      16sp —— 正文、列表副信息 */
  titleS:0.24,   /* titleSmall     15sp —— 列表主文字 */
  title: 0.27,   /* titleLarge     18sp —— 控件标题 */
  headS: 0.30,   /* headlineSmall  22sp —— 歌名、重点值 */
  head:  0.34,   /* headlineLarge  28sp —— 区块主标题 */
  dispS: 0.66,   /* displaySmall   32sp —— 大数字 */
  disp:  0.80    /* displayLarge   56sp —— 巨型统计值 */
};
function fpx(k, P){ return Math.round((TS[k] || TS.body) * P); }   /* 取像素值 */
```

> ⚠️ 命名是 `fpx` 不是 `fs` —— three.js 内部已有 `fs` 标识符。
> ⚠️ 系数是「相对排版基准 P」：`P = 画布宽/5`（子空间 `PPM=130`，主页卡 `CARD_PPM=200`）。
> ⚠️ **字号不参与布局高度计算**（`widgetHeight` 只用 `P`），故收敛字号安全。
>     唯一例外：`chipsRows` 用字号测宽，已同步为同一档位。

### 3.3 CSS 侧：`--fs-*` token（7 档）

```css
--fs-xs:11px;      /* labelSmall    11sp */
--fs-sm:13px;      /* labelLarge    13sp */
--fs-body:14px;    /* bodyMedium     14sp */
--fs-bodyL:16px;   /* bodyLarge      16sp */
--fs-title:18px;   /* titleLarge     18sp */
--fs-headS:22px;   /* headlineSmall  22sp */
--fs-head:28px;    /* headlineLarge  28sp */
```

> CSS 层现已**全部**改用 `var(--fs-*)`，无固定 `font-size:Npx` 残留。

### 3.4 改动约定

- 新增控件字号 **必须**从 `TS` 取值，不要写裸系数。
- 需要新档位时，先改 `TS` 并在本文登记，**不要**临时插一个 0.19 这种值。

## 四、泛光（Bloom）后处理

### 4.1 为什么手写

`prototype/three.min.js` 是 **r160 UMD** 构建（文档旧写「r150」有误），
**不含 examples** → `EffectComposer` / `UnrealBloomPass` / `ShaderPass` 全部不可用。

### 4.2 管线（5 pass，后 3 个在 1/4 分辨率）

```
① 场景          → rtScene（全分辨率，linear，带深度）
② 亮度提取       → rtA（软阈值 smoothstep）
③ 分离高斯·横向  → rtB
④ 分离高斯·纵向  → rtA
⑤ 合成          → 屏幕（rtScene + rtA*strength，手动 linear→sRGB 编码）
```

### 4.3 参数（`BLOOM.params`）

| 参数 | 值 | 说明 |
|---|---|---|
| `THRESHOLD` | **0.82** | **关键参数**：调研结论「不糊的关键是 threshold 0.7~0.9」（不是降 strength） |
| `KNEE` | 0.16 | 阈值软过渡带（避免硬边） |
| `STRENGTH` | 0.40 | 泛光强度（保守） |
| `DOWNSCALE` | 4 | 泛光缓冲降采样倍率（省性能） |

### 4.4 安全与开关

- **失败自动降级**：`try/catch` 包住整条管线，任一环节抛错即 `ok=false` 并退回 `renderer.render`。
- **着色器编译失败降级**：`try/catch` **抓不到**编译失败（three 只 `console.error` 不抛）
  → 由 `onShaderError` 安全网按 `LQ_BLOOM` 标识主动降级（见 §5.5）。
- **运行时开关**：`BLOOM.enabled = false`。
- **resize**：`BLOOM.setSize()` 已接入 `resize` 监听（同时补 `renderer.setPixelRatio`）。
- **降级时 `dispose()` 三个 RT**，避免显存泄漏。

### 4.5 ⚠️ MSAA（抗锯齿）必须显式开启

`renderer` 构造时带 `antialias:true`，但 **MSAA 只作用于默认 framebuffer**。
走泛光管线时，几何边缘在 `rtScene` 里就已锯齿化，最终写屏幕的只是一个全屏 quad
—— **开泛光 = 关抗锯齿**（可见回归）。

修法：只给**全分辨率、带深度的场景 RT** 开 MSAA：

```js
samples: depth ? 4 : 0     /* rtA/rtB 是 1/4 分辨率模糊缓冲，不需要 MSAA */
```

> `samples` 仅 WebGL2 生效；MSAA + `HalfFloatType` 在部分移动 GPU 上不被支持
> —— 但 `_build()` 已被 `try/catch` 包住，失败会自动降级，不会崩。

### 4.6 ⚠️ 色彩空间

走泛光管线时**渲染器不再输出 sRGB**（渲染到 RT 是 linear），
故合成 pass 里**手动做了 linear→sRGB 编码**（`toSRGB` 函数）以保持原观感。

## 五、液态玻璃（Liquid Glass）

### 5.1 依据

`docs/11` §九·五「调研结论」：最佳参考是 **Codrops「Infinite Liquid Glass Grid」的自写 SDF 假玻璃**
（单 pass、零 render target）—— 正好适配本机 r160 UMD 无 examples 的情况。

### 5.2 实现（`onBeforeCompile` 注入，不动 three 源码）

对**有贴图的面**（主页卡 / 子空间控件）注入三项：

| 效果 | 做法 | 作用 |
|---|---|---|
| **SDF 软边** | 矩形 SDF + `smoothstep` 改 `diffuseColor.a` | 内容「溶进背景」，配合已有四边擦除，彻底消除矩形硬边 |
| **边缘折射** | uv 越靠边位移越大，叠加一次采样 | 模拟厚玻璃边缘的放大/弯曲 |
| **菲涅尔边缘光** | `pow(1-dot(normal, viewDir), 3)` 加 `outgoingLight` | 掠射角亮起 → 「玻璃被光照到」 |

### 5.3 参数（`LIQUID`）

| 参数 | 主页卡 | 子空间控件 | 说明 |
|---|---|---|---|
| `edge` | 0.055 | 0.045 | SDF 软边宽度（uv）——越大越柔 |
| `refract` | 0.022 | 0.016 | 边缘折射位移强度（uv） |
| `fresnel` | 0.55 | 0.40 | 菲涅尔边缘光强度 |
| `rimTint` | `[0.72,0.80,0.92]` | 同 | 边缘光冷白色（线性） |

> 子空间控件参数更保守 —— 面板内是列表/图表等密集内容，需保可读性。

### 5.4 ⚠️ 三个必须遵守的技术约定

1. **折射采样必须「保留原 `#include <map_fragment>` 并追加」**，不能替换它
   —— 否则会丢掉 `DECODE_VIDEO_TEXTURE` / 色彩空间处理，且影响 alphaMap。
2. **`vMapUv` 的守卫必须与原 `#ifdef USE_MAP` 一致** —— 注入的采样也在 `USE_MAP` 内。
3. **法线变量是局部 `normal`（由 `normal_fragment_begin` 定义），不是 varying `vNormal`**
   —— 注入点在 `#include <opaque_fragment>` 之前，此时 `normal` / `outgoingLight` /
   `vViewPosition` 都已可用（已源码核实 r160）。

### 5.5 安全网（防「静默黑块」）

> **风险**：注入的 GLSL 若编译失败，three **不会抛异常**，只 `console.error`，
> 卡片会变成不可见的黑块 —— 这是静默失效。

做法：挂 `renderer.debug.onShaderError` 钩子（three r160 官方错误回调），
**按 shader 源码归属分派**（`onShaderError` 拿不到 material，只能嗅探源码）：

| 命中标志 | 归属 | 动作 |
|---|---|---|
| `vLqUv` / `uLqEdge` | 液态玻璃 | `LIQUID.enabled=false` + `LIQUID_FAILED=true` + 对已注入材质 `needsUpdate` |
| `LQ_BLOOM`（三个 shader 均带此注释） | 泛光 | `BLOOM.enabled=false`（setter 置 ok=false → 早退走直接渲染） |
| 其他 | 无关材质 | **不动** LIQUID / BLOOM |

> ⚠️ **两个关键设计（2026-09-23 代码审查后修正）**：
> 1. **必须用 `customProgramCacheKey` 让开关翻转触发重编译**。
>    three 的 program cache key 由 `shaderID`/`customVertexShaderID`/`defines` 等决定，
>    **不包含 `onBeforeCompile` 的函数内容** —— 只清 `onBeforeCompile` + `needsUpdate`
>    会命中同一个坏 program，「恢复」无效。现 key 返回 `'lxLq1'`/`'lxLq0'`。
> 2. **必须按来源分派**。`onShaderError` 是全局钩子，任何材质失败都会触发；
>    不分来源一律关液态玻璃会误伤（BLOOM 失败却砍 LIQUID）并造成误报
>    （`LIQUID_FAILED=true` 但实际是 BLOOM 的问题）。

> ⚠️ 该钩子仅在 `renderer.debug.checkShaderErrors` 为 true 时被调用（r160 默认 true）；
> 若被关闭，安全网静默失效 —— 安装时会 `console.warn` 提示。

### 5.6 开关

- `LIQUID.enabled = false` → **立即生效**（`customProgramCacheKey` 变化触发重编译，
  已建材质也会退回普通玻璃）；新建材质则直接不注入。
- 运行时可用 `LIQUID_FAILED` / `BLOOM_FAILED` 判断各自是否已降级。

## 六·六、空间播放器（now）倾斜参数

`now` 空间的「裸元素」用 `tilt`（绕 Y 轴的**固定**旋转，单位**弧度**，不跟随相机）
产生透视感。`docs/07_空间播放器规范.md` 是交互规范，本节登记**当前实值**。

| 元素 | tilt（弧度） | 角度 | 说明 |
|---|---|---|---|
| `lyric3d` 歌词 | **0.42** | 24.1° | 2026-09-23 由 0.32 加大（用户要求「倾斜再大一点」） |
| `cover` 封面 | **-0.32** | 18.3° | **故意不改** —— 拉开主次，让歌词比封面更「侧」 |

> ⚠️ **两处倾斜是「同向错开」而非镜像对称**：歌词 +0.42 / 封面 −0.32，
> 幅度不同（差 5.7°），不是严格镜像。这是有意为之（用户选择「歌词大、封面不变」）。

### 加大倾斜的几何约束（改数值前先看）

```
投影宽度 = fw * 2 * halfW * cos(tilt)      // 倾斜越大，投影越窄（不会越界）
两端深度差 = ww/2 * sin(tilt)              // 越大前后错落越强
halfH = tan(fov/2) * radius,  halfW = halfH * (innerWidth/innerHeight)
```

实测（fov 68 / radius 7）：

| tilt | 投影宽度 | 手机竖屏左缘余量 | 与封面间隙 |
|---|---|---|---|
| 0.32 | 94.9% | +0.188 | 6.32 |
| **0.42** | **91.3%** | **+0.230** | **6.32** |

> 结论：`0.42` 安全（余量反而更大）。理论上可加到 0.55（余量 +0.298），
> 但超过约 **0.6 rad (34°)** 后歌词接近侧面、可读性明显下降，不建议。

python3 tools/make_diag_copy.py
python3 tools/verify_now_tilt.py     # 进入 now 空间，读回各控件 tilt 并截图

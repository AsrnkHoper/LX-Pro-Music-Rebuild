## 一、项目定位（一句话）

> 把 **LX-Pro-Music（React Native 音乐播放器）** 的全部界面与交互，用**真 3D 空间语言**（Three.js）重建成一个 HTML 原型。
> **只做 UI 与交互，不接真实功能。**

**核心美学**：灰黑忧郁 · inmyfeelings · ins 冷淡 · 电影感 · **空间纵深** · 沉浸感
**当前色调**：**中性灰黑 + 冷调微光**（底色 `#08090C`，强调 `#7A828C`）

> ⚠️ **色彩订正（2026-09-22）**：本文旧版曾写「冷蓝色调 `#0A0D14` + `#6E8FAD`」，**与代码不符**。
> 代码里的真实值是中性灰（见第七节）。观感偏冷蓝主要来自**卡片内部配色**（歌单封面 `#3E4E58` 一类）
> 和**曲目主题色**（`TRACKS[].accent`），主色基建是灰的。

**最终去向（项目作者 2026-09-22 确认）**：本原型用于**验证效果**，
最终 App 要用 **Android 原生重写**（不是 WebView 直接装原型）。
因此文档里的参数/色值需要可被原生实现忠实复刻——见第十四节。

## 五、空间设计语言（务必遵守）

> 详细见 `docs/10_空间重组设计思想.md`

**三种空间形态：**
| 形态 | 用于 | 说明 |
|---|---|---|
| **A 球面环** | 主页 | 卡片环绕球面，转动浏览 |
| **B 竖列/列表空间** | 内容页 | 面板竖排，纵向转动 |
| **C 多焦点空间** | 播放页 | 正面/左侧/右侧分置，转动切换焦点 |

**6 条设计原则：**
1. 一切皆在空间里（没有"页面"，只有"空间"）
2. 转动视角 = 获取信息
3. 裸元素优先（内容不加卡片框）
4. 统一转场语言（卡片冲向镜头 → 压黑 → 新空间飞入）
5. 交互元素正对镜头（可点的不倾斜）
6. 氛围由相机统一提供（元素不各自漂浮）

**⛔ 绝对不要做的**：
- 把空间改回扁平列表
- 用 Tab 分页代替"角度"
- 用弹窗代替"环绕面"
- 1:1 复刻 LX-Pro 的页面结构（它有单屏限制，我们没有）

### B. 子空间控件（两种布局）

**布局 1：竖列模式**（搜索/统计/下载/设置/历史 —— 未标 `az`/`sf` 的空间）
```js
PAGE_W = 5.0      // 控件默认宽度（L1993）
PAGE_R = 8.4      // 球半径（L1994）
PPM    = 130      // 每世界单位像素（L1992）
gap    = 0.55     // 控件间距（L2113）
// 控件按高度自动竖排，居中
```

**布局 2：自由布局**（播放页 `now` / 歌单页 `playlist` —— 标了 `sf`/`sv` 或 `az`/`el`）
```js
PAGES.now = {
  cam: { yawMax, pitchMax, sensX, sensY },   // 该空间专属相机
  radius: 7,
  widgets: [
    { type:'lyric3d', sf:0.29, sv:0.47, fw:0.52, fh:0.32, pscale:1.7, tilt:0.32, bare:true, float:0 },
    ...
  ]
}
```

### 控件参数速查

| 参数 | 含义 |
|---|---|
| `sf` / `sv` | 面板中心的**屏幕比例**（0~1，0.5=正中） |
| `fw` / `fh` | 宽/高占**屏幕比例**（fw 相对屏宽，fh 相对屏高） |
| `w` / `h` | 直接指定世界尺寸（竖列布局用） |
| `square` | 高度=宽度（正方形） |
| `pscale` | **排版缩放**（内容放大，面板不变） |
| `bare` | **裸元素**（PlaneGeometry，无底板无厚度） |
| `tilt` | **固定倾斜**弧度（不跟随相机，产生透视） |
| `float` | 漂浮幅度，`0`=完全不漂（保持间距稳定） |
| `az` / `el` | 球面坐标定位（与 sf/sv 二选一） |

## 十一、经验教训（踩过的坑，务必避免）

| # | 坑 | 教训 |
|---|---|---|
| 1 | `m.widget` 写成 `m.userData.widget` | three.js 自定义数据**必须挂 userData** |
| 2 | 元素各自漂浮（随机相位） | 间距忽大忽小 → **同组元素用 `float:0`**，氛围靠相机 |
| 3 | 菜单卡缺 `home` / `faceMat` | 转场时 `position.copy(undefined)` 崩溃 → **卡片工厂必须给 home + faceMat** |
| 4 | 手机 touchend 后系统补发 mouseup | 点击执行两次（开关弹回）→ **用时间戳去重**（`mouseIsSynthetic`） |
| 5 | 歌词长句被裁切 | 固定字号绘制会裁切 → **绘制前 measureText 自适应缩放** |
| 6 | 主页 yawMax 限制 ±π | 环形卡片卡在180°（正好是某张卡）→ **主页 yawMax = Infinity** |
| 7 | 渲染循环抛异常 | 画面卡死 + 交互失效 → **优先怀疑 animate 内报错** |
| 8 | **文档行号漂移** | 代码一改，行号索引整节失效 → **改代码顺手更新第四节表格** |
| 9 | **误判"漏调函数"** | `read_file` 分页截断会把函数结尾切掉 → **判断前先读全函数体** |

### 14.3 技术概念映射（原型定稿后写入原生时用）

| 原型里的做法 | 作用 | Android 对应思路 |
|---|---|---|
| 相机 yaw/pitch + 球面坐标 | 转动视角浏览 | 手势 drag → 角度；`graphicsLayer { rotationY/rotationX }` + `cameraDistance` |
| `tilt` 固定倾斜 | 不跟随相机的透视感 | `graphicsLayer { rotationY = tilt }` |
| `m.lookAt(camera)`（billboard） | 始终正对镜头 | 不加旋转，天然正对 |
| 射线拾取 `raycaster` + `hit.uv` | 3D 里点控件 | **难点**：需把控件位置投影到屏幕坐标做矩形命中测试 |
| `bare:true`（PlaneGeometry） | 裸元素，无底板 | 无背景的 Compose `Text`/`Image` |
| 非 bare（`BoxGeometry` 0.06 厚） | 有厚度的卡片 | 改用 **Haze 玻璃卡片**（原生已有方案） |
| `PlaneGeometry` + `CanvasTexture` | Canvas 画 2D 当贴图 | **直接用 Compose 组件**（省掉贴图烘焙，可交互性更好） |
| `tex.offset.y` 滚动歌词 | GPU 侧零重绘滚动 | `LazyColumn` + `graphicsLayer` 平移 |
| 每帧改 `mesh.scale/position` | 漂浮/入场动画 | `animateFloatAsState` / `Animatable` |

> ✅ **技术判断（2026-09-22 订正）**：Compose 的 `graphicsLayer` **能做真透视**
> （`RenderNode` 4×4 矩阵 + `cameraDistance` 驱动透视除法），**不需要 Filament**。
> 球面环绕若移植到原生，用 `graphicsLayer` 自算投影即可（几十张平面卡片规模足够）。
>
> **唯一实质局限**：Compose 是 2D 合成器，**无深度缓冲**——
> 卡片间遮挡只能靠 `zIndex` 按 Z 排序后依次绘制，无法逐像素正确遮挡。
> 另外每个卡片是独立 Layer，各自有 `transformOrigin`/`cameraDistance`，
> 需统一 pivot 到屏幕相机心，否则会出现"各自的消失点"。
>
> 只有需要**真实几何体/曲面、逐像素遮挡、光照/PBR、上千 draw call** 时才需 Filament。
> **几十张平面卡片绕球面转动 —— `graphicsLayer` 足够。**

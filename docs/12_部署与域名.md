## 一、部署链路

```
本地工作区  ~/Hoper/LX_Pro_Rebuild_UI
    │  git push origin main
    ▼
GitHub      AsrnkHoper/LX-Pro-Music-Rebuild   (public)
    │  Vercel 监听 main 分支，自动构建部署
    ▼
Vercel      lx-pro-music-rebuild.vercel.app   (静态站点，无需构建命令)
    │  Cloudflare 反向代理（橙云 Proxied）
    ▼
线上        https://lx-pro.hoper.eu.org
```

**纯静态站点**：Framework Preset 选 `Other`，Build Command / Output Directory 留空。
入口是仓库根目录的 `index.html`。

## 二、⚠️ 为什么必须绕 Cloudflare（核心）

**`vercel.app` 在本机网络下不可直达**（实测 3 次全部超时）：

| 域名 | 本机直连 |
|---|---|
| `vercel.com` | ✅ 200 |
| **`vercel.app`** | **❌ 000 超时** |
| `lx-pro-music-rebuild.vercel.app` | ❌ 000 超时 |
| 经 CF 边缘访问同一地址 | ✅ 200 |

本机网络是**域名级 SNI 白名单防火墙**（详见 `~/Hoper/General/网络与外网连接.md`）——
`vercel.app` 不在白名单内。

**结论**：自定义域名不是"好看"，而是**本机能否访问的前提**。
走 Cloudflare 边缘（其 IP 段可达）才能正常打开。

**性能实测**：`three.min.js`（669 KB）经 CF 下载 **1.57 秒**，与本地文件逐字节一致。

## 三、Cloudflare 侧配置

域名 `hoper.eu.org` 托管在 Cloudflare（NS：`kevin.ns.cloudflare.com` / `summer.ns.cloudflare.com`）。

### 3.1 DNS 记录

| Type | Name | Target | Proxy |
|---|---|---|---|
| `CNAME` | `lx-pro` | `lx-pro-music-rebuild.vercel.app` | **Proxied（橙云 🟠）** |

> ⚠️ **必须开橙云**。灰云（DNS only）会直接暴露 Vercel 的 IP，等于没走 CF，本机就打不开。

### 3.2 Host 头改写（反代必需）

反代到 Vercel 时，CF 默认传 `Host: lx-pro.hoper.eu.org`，
**Vercel 会因 Host 不匹配返回 404**。需要改回真实 Host：

**Rules → Transform Rules → Modify Request Header → Create rule**
- 名称：`vercel-host`
- 匹配：`Host` `equals` `lx-pro.hoper.eu.org`
- 动作：**Set static** `Host` = `lx-pro-music-rebuild.vercel.app`

### 3.3 SSL 模式

**SSL/TLS → Overview → `Full`**（不是 Full Strict）。

### 3.4 Vercel 侧（可选但建议）

Vercel → 项目 → **Settings → Domains → Add** → `lx-pro.hoper.eu.org`。
让 Vercel 知道该域属于本项目，内部链接/重定向更正确。
> 加它会提示配 CNAME —— **忽略该提示**，DNS 已在 Cloudflare 配好。

## 四、验证方法

```bash
# 1) 主页
curl -s -o /dev/null -w "%{http_code}\n" https://lx-pro.hoper.eu.org
# 期望 200

# 2) 原型主文件
curl -s -o /dev/null -w "%{http_code}\n" https://lx-pro.hoper.eu.org/prototype/app.html
# 期望 200

# 3) 确认走的是 CF 边缘（关键）
curl -sI https://lx-pro.hoper.eu.org | grep -i "^server:"
# 期望 server: cloudflare

# 4) 确认内容是最新部署
curl -sI https://lx-pro.hoper.eu.org | grep -i "last-modified"
```

**逐字节校验**（确认没被 CDN 截断/改写）：
```bash
curl -s https://lx-pro.hoper.eu.org/prototype/three.min.js -o /tmp/t.js
sha256sum /tmp/t.js prototype/three.min.js
# 两个 sha256 应相同
```

## 五、改动与发布流程

```bash
cd ~/Hoper/LX_Pro_Rebuild_UI
# 改 prototype/app.html ...
git add -A && git commit -m "..."
git push origin main        # Vercel 自动重新部署，约 1 分钟后域名同步生效
```

> ⚠️ **推送走 SSH**（`git@github.com:...`）。本机 `github.com` 的 **HTTPS 直连会超时**，
> 但 **SSH 22 端口正常**（实测握手 3.7s）。`gh` 也走 SSH，建仓/推送都没问题。

## 六、踩坑记录

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **`vercel.app` 不可直达** | 直连超时，以为部署失败 | 实际是网络挡的；经 CF 代理访问返回 200 才确认服务正常 |
| 2 | **泛解析干扰判断** | 任意子域（含编造的随机名）都解析到 CF 并返回 404 | 说明 `*.hoper.eu.org` 有泛解析兜底 —— 判断"子域是否已占用"要看**是否返回真实内容**，不能只看解析 |
| 3 | 反代时 Vercel 返回 404 | Host 头不匹配 | 加 Cloudflare Transform Rule 改写 Host（见 3.2） |
| 4 | 灰云等于没代理 | 开了 CNAME 但直连仍超时 | 必须开**橙云** |
| 5 | `git clone` 在本机被权限策略拦 | — | 用 GitHub API（`/git/trees/main?recursive=1`）核对远端文件清单与 blob sha |

# test/ — app.html 回归测试

> 目的：**每次改完 `app.html` 先跑这个**，通过再推送。
> 起因：2026-09-22 连续两轮改动都引入了 bug（黑屏 / 导航条 NaN）却直接推给了用户。

## 用法

```bash
cd prototype
node test/run.js
```

退出码 0 = 全过；非 0 = 有失败（可直接接 CI）。

## 覆盖范围

| # | 测试 | 防的是什么 |
|---|---|---|
| 1 | 全部空间构建 | 控件绘制抛异常 → 黑屏 |
| 2 | 主页卡片数量/方位 | 卡片配置被改错 |
| 3 | 进入 → 返回 | 返回后卡片消失 |
| 4 | 长列表滚动 / 惯性 / 导航条 | 导航条 NaN、惯性停不下来、跳转越界 |
| 5 | 播放页迷你歌词 | 歌词索引不同步、超长句裁切 |
| 6 | 空间切换 | 某空间无可见 mesh |

## 原理

`harness.js` 提供最小的 `THREE` + DOM 模拟，让 `app.html` 里的**真实函数**
（`buildPage` / `scrollList` / `animate` / `nowTick` …）能在 node 里执行。

- 时间用**假时钟**（`Date.now` 可控）→ 惯性等依赖时间的逻辑可确定性测试
- `setTimeout` 被接管 → 可手动 `drain()` 推进转场时序
- `raycaster.intersectObjects` 可打桩（`global.__HIT`）→ 模拟点中某控件

## ⚠️ 注意

- 这是**测试桩**，不是真浏览器。**观感类问题（颜色/字号/手感）测不出来**，仍需真机验收。
- 若 `app.html` 新增了依赖浏览器 API 的代码，可能需要在 `harness.js` 里补桩。
